# ADR-0006 — Programming Peer Admission and Website Building Capability

Status: ACCEPTED
Effective date: 2026-09-13
Authority: explicit user-directed architecture repair
Supersedes for Programming admission: the prior non-peer Programming disposition in Topology 006 and associated current control records.
Preserves: ADR-0005 Prose terminal retirement and all non-conflicting owner boundaries.

## Decision

1. `PROGRAMMING` is admitted as the ninth direct peer system under `SYSTEM_MASTER`.
2. The preserved Programming work program is not restarted or discarded. Its foundation/build/test/assurance/Genesis evidence becomes continuity input for the admitted Programming system.
3. Programming receives canonical owner path `SYSTEM_MASTER/PROGRAMMING`, control ref `programming/control-v1`, a dedicated Second Shift owner lane, repair/qualification routing eligibility, and current product-level incomplete standing.
4. `WEBSITE_BUILDING` is admitted as reserved capability `C40`, owned by `SYSTEM_MASTER/PROGRAMMING`.
5. Website Building is a first-class Programming capability, not a tenth peer system.

## Website Building boundary

Website Building owns website/web-application construction semantics: application/site structure, frontend/backend composition, generated code, build/test engineering, deployment preparation, technical validation and maintenance engineering.

It does not own browser action policy, user-authorized side effects, credentials, production publication authority or external-provider authority. Browser interaction remains a `CONNECTED_ACTIONS` capability consumed through admitted interfaces. Research/provenance remains `RESEARCH_KNOWLEDGE`; media assets remain `MEDIA`; generic document artifacts remain `DOCUMENTS`; shared runtime/A-01/storage/model infrastructure remains `CORE`.

## Programming boundary

Programming owns software-engineering semantics including project/build/dependency/toolchain, code construction/transformation, testing and effectiveness, static/dynamic/fuzz/security/performance/compatibility/reliability analysis, diagnosis/repair, release/deployment/operations/maintenance engineering, technical documentation and Programming-specific qualification.

Programming consumes shared Core infrastructure without transferring semantic ownership. The existing Knowledge Recovery subprogram remains Core-administered custody/provenance support and does not become the Programming product owner.

## Execution readiness

Programming is admitted execution-ready in the same architecture transaction because this transaction establishes:
- a canonical Programming control record,
- a current Programming owner path/control ref,
- a Programming Second Shift owner file and exact control-head binding,
- current obligation and completion records,
- current capability ownership for AUTOMATION, CODE and WEBSITE_BUILDING.

Repository execution readiness does not synthesize external, production, publication, credential, native or user-action authority.

## Historical continuity

Prior records describing Programming as an active non-peer work program remain historical evidence of the pre-admission state. They must not be interpreted as current authority after `CURRENT-AUTHORITY-005` selects Topology 007.

No prior Programming PASS or historical exact-SHA result automatically transfers to changed post-admission bytes. Reuse remains subject to exact-subject qualification rules.
