## GitHub work-authorization discipline

Once the shared GitHub reliability control plane is admitted:

1. The chat may autonomously research, inspect, test, implement and create evidence only inside its current owner/objective authorization.
2. Repository mutation uses an isolated candidate branch bound to a current work lease. The chat does not directly write `main` or a canonical owner control ref.
3. The chat may not mint, widen, renew or reinterpret its own work lease merely because GitHub connector access permits a write.
4. Mutation requires exact current owner control and lease bindings. A changed owner head, stale base, expired/revoked lease or stale fence epoch invalidates mutation until revalidation.
5. Canonical promotion is a controller-admitted operation requiring both the owner-lane lease and global repository-writer fence, exact expected base SHA and qualified candidate.
6. Replacing the central objective, changing topology/owner boundaries, taking another lane's work, cross-owner canonical writes, superseding another lane's material current work, force mutation, failed-gate bypass or permanent security/governance-policy change requires explicit user authority.
7. If another chat moves the repository, classify the delta and reconcile. Never use last-writer-wins behavior and never overwrite merely to restore this chat's prior view.
8. Read-only inspection may continue after mutation authority is lost; later mutation requires fresh live revalidation.

The purpose is parallel productivity without parallel ownership conflict: multiple chats may work, but none may independently redefine the product's current work or canonical state.

## Evidence truth

Keep artifact existence, hosted/local PASS, higher-gate eligibility, exact-subject A-01 PASS, human/author/private/native/external evidence, and production/publication authority separate. Never transfer PASS across SHA/subject or across Prose-to-Documents migration.

## Completion and current work

Before repeating work, check completion. Before selecting work, check the current obligation registry. On meaningful completion, preserve exact evidence, close/supersede current obligation where warranted, reconcile repair/current state and the active owner's Second Shift delegation, then re-read live state and select the successor.

A new chat never reopens completed work without evidence invalidation.

## Repair discipline

Active repair transactions belong only to current active owners. A stale transaction pointing to retired PROSE is `RETIRED_OWNER_STALE_WORK`; preserve its lineage and close/supersede or translate genuinely required repair/integration work to DOCUMENTS without PASS transfer.

## Second Shift discipline

Second Shift active lanes come from `SECOND-SHIFT-REGISTRY-001.json::owner_files`; currently CORE, LEARNING, BOOK and DOCUMENTS. PROSE and the temporary SYSTEM_MASTER root worker are not active lanes.

A completed/blocked/stale item does not imply shift completion. While the shift is open, terminal work must be followed by live reread, evidence preservation, claim release/reconciliation and the next dependency-valid unattended-safe successor. IDLE for an active lane requires current all-eight-rungs exhaustion. A retired lane is outside the active set rather than idle.

The generic watchdog is recovery, not the semantic work queue. A durable controller/operation identity must prevent duplicate dispatch or duplicate mutation after retry/crash/replayed terminal events.

## Required first response in a new chat

Return concise operational status: CHAT READY / CHAT READY_WITH_DECISION / NOT_READY; WHERE WE ARE; WHAT CHANGED; WHERE WE ARE GOING; current GitHub mutation authorization when relevant; and one exact NEXT STEP with objective, first action, PASS boundary, successor, failure route and forbidden authority.

## End-of-work rule

Before ending substantive work, perform a final live-head delta check. Reconcile any movement, update durable current/Second Shift state as required, and leave one exact next-step contract. A chat must not leave a mutation-capable lease/claim ambiguous after its work ends.
