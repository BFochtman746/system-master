# Foundation & Spine

This directory is the fresh design authority for the System Master Foundation & Spine.

## Documentation reset

The Foundation & Spine documentation was rebuilt from first principles because prior design material accumulated through repeated extension, repair, renaming, and partial reclassification.

The documents in this directory supersede all earlier Foundation & Spine **design descriptions** as normative architecture. Earlier documents, reports, research packets, qualification receipts, logs, routing records, source history, and forensic evidence remain valid as historical/source evidence where their exact claims are still supported, but they do not define the architecture merely because they came first.

No runtime code, logs, routes, evidence, qualification receipts, or historical records are replaced by this documentation reset.

## Canonical documents

1. `FOUNDATION-SPINE-SPECIFICATION.md` — what the Foundation & Spine is, what systems must exist, what each owns, and how work moves through the system.
2. `COMPLETION-STANDARD.md` — what must be true before the Foundation & Spine, or any of its systems, may be called designed, implemented, qualified, production-admitted, or complete.

No additional Foundation & Spine design document is authoritative unless these documents explicitly incorporate it.

## Interpretation rule

Historical names and packet IDs are discovery aids only. If an older document conflicts with the architecture defined here, this documentation governs the intended design. Historical evidence may still prove that an implementation exists or passed a particular test, but it cannot silently change ownership or architecture.

## A-01 rule

A-01 is a qualification environment, not an architectural authority. If A-01 was unavailable or disconnected, the correct standing is `TARGET QUALIFICATION NOT EXECUTED — ENVIRONMENT UNAVAILABLE`. That condition is not a failure of architecture or implementation and must never be rewritten as one.
