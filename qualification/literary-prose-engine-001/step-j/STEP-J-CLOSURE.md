## Closed objective

`LITERARY-PROSE-ENGINE-001-STEP-J — VOICE EVOLUTION + PREFERENCE LEARNING / STABLE IDENTITY + CURRENT PREFERENCE + DEVELOPMENT FRONTIER + REJECTED DIRECTION / CHRONOLOGICAL LEARNING QUALIFICATION`

STEP-J converts qualified evaluator outcomes and explicit user decisions into an append-only, project-specific learning ledger and deterministic derived state. It extends the canonical STEP-C/master voice hierarchy without replacing the existing project voice profile.

## Qualified behavior

- chronology is append-only and deterministically replayable;
- explicit user decisions are the highest project-preference authority;
- user actions outrank STEP-I-qualified machine evidence;
- frequency is evidence volume, not a quality vote, and cannot outvote higher-authority preference evidence;
- one accepted revision cannot become a permanent stable-identity rule;
- `STABLE_IDENTITY` requires an explicit user identity invariant, and contradictory redefinition requires explicit supersession;
- `CURRENT_PREFERENCE` is conditioned by project and context rather than blindly globalized;
- `DEVELOPMENT_FRONTIER` retains conflicting non-governing directions for deliberate exploration;
- `REJECTED_DIRECTION` preserves user-rejected directions as anti-preference evidence while retaining rejection history after later supersession or revocation;
- a rejected direction is never treated as a positive `CURRENT_PREFERENCE` merely because it is the only event for that dimension/context;
- revocation appends a new event, preserves prior history, and deterministically reveals the next valid governing evidence;
- revoking a rejection removes it from the active anti-preference set but retains it in immutable rejection history with revoked status;
- accepted, rejected, modified, retain-original, and STEP-I outcomes all remain chronological evidence;
- named-author targeting is rejected;
- raw manuscript/candidate/original text is forbidden from the preference-learning event ledger; digests and evidence references are used instead.

## Authority order

`USER_EXPLICIT > USER_ACTION > STEP_I_QUALIFIED`

This order is intentional: the system may learn from its own qualified outcomes, but repeated machine agreement cannot silently redefine what the user says this project should be.

## Qualification

Twenty-five deterministic synthetic base fixtures pass. They cover explicit preference, non-promotion of a single preference into stable identity, user-action precedence, frequency resistance, later explicit preference updates, explicit identity, identity supersession, rejected directions, later acceptance, contextual isolation, user-modified candidates, retain-original learning, duplicate/chronology failures, raw-text rejection, named-author rejection, authority mismatch, project isolation, revocation, deterministic replay, repeated system wins, and development-frontier retention.

A subsequent audit identified one semantic gap: `USER_REJECT_CANDIDATE` had been eligible to govern `CURRENT_PREFERENCE`. Implementation commit `062f622bd7526528e7c5eee2e348bcca18c475d5` removes rejection events from the positive preference ranking and makes rejection history derive from the full chronological ledger rather than active events only. The unchanged 25-case base suite still passes, and two targeted hardening regressions also pass, for **27 passing synthetic cases total**.
