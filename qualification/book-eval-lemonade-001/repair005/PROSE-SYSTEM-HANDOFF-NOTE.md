# Literary Prose System handoff

The prose optimizer must be developed in a separate branch/thread from evaluator qualification.

Authoritative shared contract:
`qualification/book-eval-lemonade-001/repair005/LITERARY-REFERENCE-CORPUS-CONTRACT-v1.json`

The prose system must reuse the shared literary intelligence architecture without importing scoring-private gold or evaluator hidden-holdout material.

Recommended bootstrap objective:
`BOOKS-LITERARY-PROSE-001 — RIGHTS-SAFE MASTERPIECE + CRAFT REFERENCE CORPUS / PROSE OPTIMIZATION ENGINE FOUNDATION`

Core architectural requirements:

- full-text ingestion only for verified public-domain, licensed, or user-owned/authorized sources;
- modern copyrighted works without sufficient rights remain analysis/metadata/abstract-technique only;
- learn transferable craft patterns, not named-author imitation;
- organize references by genre, audience, passage function, technique dimensions, observable effects, failure modes, and revision transforms;
- writer, critic, and revision-comparator must be logically separated;
- optimize relative to project voice/canon/intent/protected language rather than one universal prose ideal;
- retain original prose when a proposed revision does not demonstrate measurable improvement;
- build reusable outputs for both drafting/revision and evaluator evidence construction;
- provenance and rights status must be machine-enforced for every stored source/derived artifact.

The new prose branch/thread should first inventory existing System Master writing/book components before implementing a parallel subsystem, then create the architecture/build order and begin with corpus/rights/provenance foundation rather than model tuning.
